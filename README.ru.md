# Telegram Ban Bypass

## Обзор

Улучшенный веб-инструмент, который позволяет просматривать контент любого публичного Telegram-канала — даже если ваш аккаунт забанен в этом конкретном канале. Включает оптимизацию производительности и улучшенные функции.

**Демо:** [DEMO](https://franbarinstance.github.io/Telegram-Ban-Bypass/public/)

## Установка

Установка не требуется. Можно:
1. Воспользоваться **[живой веб-версией](https://franbarinstance.github.io/Telegram-Ban-Bypass/public/)**, или
2. Скачать **[единственный HTML-файл](https://github.com/franbarinstance/Telegram-Ban-Bypass/blob/master/public/index.html)** и открыть его в любом браузере

## Возможности

- **Без входа** - для чтения каналов не нужен аккаунт Telegram
- **Многопроходный поиск, устойчивый к пропускам** - находит последнюю запись даже через разрывы из удалённых сообщений
- **Продолжение с места остановки** - повторное открытие канала мгновенно загружается от сохранённого последнего ID; остановленный поиск сохраняет прогресс, и следующий поиск продолжается с него, а «Искать заново» перепроверяет от сохранённого последнего ID и корректирует его, если сообщения были удалены, каждый раз проверяя другие ID
- **Проверить новые сообщения** - следующие записи появляются мгновенно, пока проверка продолжается в фоне; ручная кнопка, необязательный таймер автопроверки и расширенная проверка с настраиваемым лимитом (до 1000 записей вперёд), которая перепрыгивает большие разрывы
- **Ручной режим Start ID** - для каналов, где автоматический поиск буксует, начинайте с известного ID сообщения
- **Обратная связь в реальном времени** - показывает прогресс поиска
- **Светлая и тёмная темы, 9 языков** - следует настройкам системы, устанавливается как PWA
- **Оптимизация под мобильные** - работает на всех устройствах
- **Без установки** - работает прямо в браузере

## Как это работает

Инструмент использует [API Telegram Widgets](https://core.telegram.org/widgets/post), предназначенное для встраивания отдельных записей Telegram.

В каналах и группах Telegram ID сообщений последовательны. Это значит, что, зная ID последней записи, можно показать любое число предыдущих сообщений через виджет записи Telegram.

#### Задача: найти ID последнего сообщения

Главное препятствие — определить ID самого свежего сообщения в канале или группе. Официальные API Telegram могли бы дать эти данные, но у них есть ограничения:

- лимиты частоты ограничивают частые запросы;
- ограничения CORS осложняют реализацию на клиентском JavaScript.

#### Решение: обходной путь на основе виджета

Чтобы обойти эти ограничения и не зависеть от API, инструмент использует виджет записи Telegram для определения последнего сообщения. *Проба* загружает виджет для предполагаемого ID сообщения в скрытом контейнере и считывает высоту полученного iframe:

- высокий iframe (изменённый встраиванием) → сообщение существует;
- узкий iframe → Telegram отрисовал страницу «post not found»: сообщения не существует;
- iframe стандартной высоты ~150 px (никогда не изменялся) → неоднозначно: запрос на встраивание был ограничен или канал не существует. Неоднозначные ответы повторяются один раз, прежде чем считаться отсутствующими.

Такая детекция никогда не читает содержимое виджета (CORS не позволяет) — только размер iframe.

Имея детекцию существования, поиск идёт проходами с убывающим разрешением, допуская разрывы из удалённых сообщений:

1. Сетка якорей – небольшая сетка пробных ID находит заведомо существующее сообщение.
2. Восходящий проход – крупные пробы (шаг 100k) ограничивают область выше последнего существующего сообщения.
3. Уточнение – последовательные проходы с шагом 10k, 1k, 100 и 10 сужают область.
4. Финальное сканирование – сканирование с шагом 1 определяет точный ID последнего сообщения.

Каждый проход идёт вперёд и останавливается после серии подряд неудач (по умолчанию 10) — именно это позволяет перепрыгивать разрывы удалений: на проходе 1k он может преодолеть разрыв примерно в 10 000 удалённых сообщений, на проходе 100 — около 1 000, и так далее. Пробы выполняются параллельными пачками по 5. Кнопка «Стоп» прерывает поиск в любой момент; наибольший проверенный до сих пор ID сохраняется, и следующий поиск этого канала продолжается с него, а не начинается заново.

#### Почему поиск может быть медленным

Каждая проба — настоящий запрос на встраивание к t.me, и один ответ занимает примерно от 0,1 до 1,5 секунды. Полный поиск стоит около 150–250 проб, поэтому обычно занимает десятки секунд. Замедляют его две вещи:

- **Ограничения частоты Telegram.** После множества запросов t.me начинает отбрасывать ответы встраивания (тот самый неоднозначный случай ~150 px). Пробы тогда тратят полное ожидание плюс повтор, и весь поиск может растянуться на минуты. Лимиты действуют по IP и снимаются сами через некоторое время.
- **Разрывы из удалённых сообщений.** Большие разрывы требуют больше уточняющих проб, прежде чем будет достигнут порог серии неудач.

Повторное открытие уже просмотренного канала мгновенно: последний ID сообщения сохранён и используется снова, ноль проб. «Проверить новые сообщения» после этого работает лишь с несколькими ID выше него: следующие десять ID сразу отображаются в ленте (несуществующие записи сами скрываются), поэтому всё новое появляется сразу, а сканирование в фоне продолжает определять настоящее последнее сообщение. Эти десять встраиваний одновременно служат пробами существования для своих ID, так что проверка не стоит дополнительных запросов.

#### Известные проблемы поиска

- **Каналы с массовыми удалениями.** Если в канале разрыв удалений больше, чем способен преодолеть проход — например, чистка спама удалила большую часть истории, оставив свежую запись в одиночку в тысячах ID выше последнего уцелевшего блока, — поиск остановится ниже настоящего последнего сообщения. Дёшево такой разрыв не обнаружить; для таких каналов используйте ручной режим Start ID.
- **Очень большие каналы.** Каналы, чей последний ID сообщения превышает 3 миллиона, помечаются как «слишком большой» и не ищутся; и снова — ручной режим Start ID справляется.
- **Несуществующие или приватные каналы.** Telegram отдаёт страницу предпросмотра для *каждого* ID сообщения несуществующего канала, поэтому все пробы выглядят «высокими». Поиск обнаруживает это пробой-стражем на ID, которого не может быть у реального канала, и сообщает, что канал не найден.

## Технологии

- Использование публичного API виджетов Telegram, которое не подвержено банам
- Динамическая загрузка записей в обратно-хронологическом порядке
- Автоматическое определение и удаление удалённых записей
- Единственный HTML-файл без зависимостей (ванильные JS/CSS), устанавливается как PWA

## Ограничения

- Работает только с публичными каналами
- Возможны проблемы при медленном интернет-соединении.
- Некоторые очень старые записи могут не загружаться
- Нет возможности скачивать медиа
- Каналы с экстремально массовыми удалениями (например, чистки спама, удалившие больше половины всех сообщений) могут обойти автоматический поиск; используйте ручной режим Start ID
